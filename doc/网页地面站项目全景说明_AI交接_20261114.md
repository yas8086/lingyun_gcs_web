## 0. 给接手 AI 的 30 秒结论

1. 这是一个 **Node.js 20 + 原生前端（无框架、无构建、无 npm 依赖）** 的 Web 地面站。
2. 浏览器**永远不接触 MQTT**。后端独占 MQTT over TLS 连接，浏览器只通过同源 `/api/*` 和 SSE `/api/stream` 拿数据。
3. 页面有 5 个：**监控、自检、飞控、图示、设置**。摄像头页、回放页、窗口控制按钮均已移除。
4. 当前线上部署在 **FunctionWeb / Node.js 20**，私有站点。MQTT 凭据**不在代码、不在环境变量、不在部署记录**里，而是由站点所有者在 `/setup` 页面一次性填入，**只存在后端进程内存**。
5. 因此：**每次重新部署或实例重启，MQTT 配置都会清空**，需要重新打开 `/setup` 填一次。这是当前方案最重要的运维约束。
6. 代码里没有 Java，也没有任何 `.java` 文件；桌面地面站是 Qt/C++/QML，Web 端是完全独立的 Node 实现。
7. 真实 MQTT 已经实测通过：只读账号可订阅 `bt600/telemetry`，发布被拒绝；后端能收到 0.5 Hz 帧。设备全离线时页面显示 `0 / 15`，不出现 `undefined/NaN`。
8. 不要把任何真实密码写进代码、文档、Git、前端或日志。`/setup` 页面就是为此设计的。

## 1. 项目定位

### 1.1 它是什么

灵云01号（BT600 载重飞艇）的 **Web 版地面站看板**，用于：

- 实时监控电源系统（主电池、备用电池、两路 MPPT、DCDC、配电拓扑）
- 查看飞控姿态、GPS、电机、地图轨迹
- 查看温度/气压采集节点
- 运行起飞前自检
- 查看告警与运行日志
- 在开放指令通道时执行电源控制（当前线上默认关闭）
- 用和桌面端一致的视觉语言做远程/大屏展示

### 1.2 它不是什么

- 不是桌面端 Qt 程序的替代品：没有视频、云台、摄像头页。
- 不是历史数据平台：回放页已删除；后端仍有内存会话缓存 API，但**不落盘、不跨重启**。
- 不是 MQTT 直连前端：浏览器拿不到 Broker、端口、用户名、密码、主题。
- 不是多租户系统：没有登录/权限系统，完全依赖 Trae 站点的“私有”访问策略。
- 不是高可用集群方案：当前 MQTT 配置是进程内存态，多实例会不一致。

### 1.3 与桌面端的关系

- 视觉与信息架构对齐桌面端 `src/qml/main.qml` 与 `TopoView.qml`。
- 主题、5 种强调色、密度、状态栏、监控卡片、能源拓扑节点坐标均来自桌面端。
- 协议解析以机载对接文档为准，Web 端只做展示与轻量推导。
- 桌面端使用 Qt/C++/QML；Web 端使用 Node.js + 原生 JS，二者代码不共享。

此时页面显示“MQTT 未配置”，不会用模拟数据冒充实时数据。打开 `http://127.0.0.1:8000/setup` 填只读账号。

```bash
MQTT_HOST=your-broker.example.com \
MQTT_PORT=8883 \
MQTT_TLS=true \
MQTT_USERNAME=bt600_web \
MQTT_PASSWORD='只读密码' \
MQTT_TOPIC=bt600/telemetry \
MQTT_ENABLED=true \
PORT=8000 node server.js
```

也可以使用完整的 `MQTT_URL`：

```bash
MQTT_URL='mqtts://user:pass@host:8883' MQTT_TOPIC='bt600/telemetry' node server.js
```

> 注意：`MQTT_URL` 里的密码必须 URL 编码；服务端会解码。

## 4. 运行时架构

### 4.1 数据流

```text
BT600 机载 ROS2
   │  MQTT over TLS（8883）
   ▼
EMQX Cloud（深圳）
   │  服务端订阅 bt600/telemetry
   ▼
Node.js 后端（本项目的 server.js）
   │  解析 / 去重 / 在线判定 / 告警 / 曲线 / 会话
   │  同源 HTTP + SSE
   ▼
浏览器（原生 JS）
   │  EventSource /api/stream
   ├─ state      首屏快照
   ├─ telemetry  每帧
   ├─ status     每秒
   ├─ log        新日志
   ├─ alarm      新告警
   ├─ alarms-sync 告警确认同步
   └─ power-result 指令结果
```

### 4.2 三种数据源模式

| 模式 | 触发条件 | `source` | 行为 |
| --- | --- | --- | --- |
| 环境变量 MQTT | `MQTT_*` 配置有效 | `mqtt` | 启动即连接；连不上也不回退模拟源 |
| 运行时配置 | 部署设置 `REQUIRE_MQTT=1`，等待 `/setup` | `unconfigured` → `mqtt` | 未配置时页面明确提示；提交后停止模拟源并内存连接 |
| 内置模拟源 | 没有 MQTT 配置且未设置 `REQUIRE_MQTT=1` | `sim` | 5 Hz 生成完整演示数据 |

启动逻辑在 `server.js` 的 `start()`：

```js
if (mqttCfg.enabled) {
  setupMqtt();
} else if (process.env.REQUIRE_MQTT === '1') {
  telemetry.setSource('unconfigured');
  telemetry.log('warn', 'MQTT 未配置，请打开 /setup 填写只读连接参数', '后端');
} else {
  telemetry.startSimulator();
}
```

### 4.3 进程生命周期

- 单进程 Node HTTP 服务，无 worker、无框架。
- `SIGTERM` / `SIGINT`：停止 MQTT、关闭 HTTP、最多等 3 秒退出。
- 部署平台会替换实例；**所有内存态（MQTT 配置、遥测、曲线、会话、告警）都会丢失**。
- 静态文件从 `public/` 读取，`dist/` 是部署构建产物。

## 5. 后端深挖：`server.js`

### 5.1 环境变量总表

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8000` | HTTP 端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `MQTT_ENABLED` | `auto` | `false` / `0` 强制关闭；否则有 URL 即启用 |
| `MQTT_URL` | 空 | 完整 URL，优先级最高；支持 `mqtt://` / `mqtts://` / `tls://` / `ssl://` |
| `MQTT_HOST` | 空 | 主机名；与 `MQTT_URL` 二选一 |
| `MQTT_PORT` | 空 | 端口；默认 8883（TLS）或 1883 |
| `MQTT_TLS` | 空 | `true` 强制 TLS；端口 8883 也自动 TLS |
| `MQTT_TLS_INSECURE` | 空 | `true` 时 `rejectUnauthorized=false`（不推荐） |
| `MQTT_USERNAME` | 空 | 用户名 |
| `MQTT_PASSWORD` | 空 | 密码 |
| `MQTT_TOPIC` | `lingyun01/telemetry` | 遥测主题；当前生产实际为 `bt600/telemetry`，由 `/setup` 或环境变量指定 |
| `MQTT_CMD_TOPIC` | 空 | 指令下行主题；为空则指令通道关闭 |
| `MQTT_ACK_TOPIC` | 空 | 指令 ACK 主题；为空则不订阅 ACK |
| `MQTT_ACK_TIMEOUT` | `6000` | 指令 ACK 超时毫秒；最小 2000 |
| `ALLOW_COMMANDS` | 空 | `true` 才允许 `/api/command` 下发 |
| `REQUIRE_MQTT` | 空 | `1` 时未配置 MQTT 不回退模拟源 |

### 5.2 `readMqttConfig()`

逻辑：

1. 读取 `MQTT_URL`；有则直接使用。
2. 否则用 `MQTT_HOST` 拼接：
   - TLS 判定：`MQTT_TLS === 'true'` 或端口 8883。
   - 有用户名时拼 `username:password@`（两者都 `encodeURIComponent`）。
   - 默认端口：TLS 8883，非 TLS 1883。
3. `enabled` 仅在 `MQTT_ENABLED` 不为 false/0 且 `finalUrl` 非空时为 true。
4. `rejectUnauthorized` 默认 true，只有 `MQTT_TLS_INSECURE=true` 才关闭。

### 5.3 运行时配置（`/setup` 的核心）

```text
GET  /api/mqtt/config      → { configured, connected, source }   （不回显主机/账号/主题）
POST /api/mqtt/configure   → { ok: true } 或 { ok:false, message }
```

`POST` 的安全与校验：

- **同源校验**：如果请求带 `Origin`，其 `host` 必须等于 `req.headers.host`；否则 403。
- **限频**：两次提交间隔 < 2 秒返回 429。
- **Body 上限**：64 KB。
- **字段校验**（`buildMqttConfig`）：
  - `host` 只允许字母、数字、点、短横线。
  - `port` 必须是 1–65535 整数。
  - `username` / `password` 非空。
  - `topic` 非空，且不能包含 `#`、`+`、空白。
  - `tls` 默认 true。
- 生成配置：

```js
{
  enabled: true,
  url: 'mqtts://user:pass@host:port',
  topic,
  cmdTopic: '',
  ackTopic: '',
  allowCommands: false,
  rejectUnauthorized: true
}
```

- 调用 `setupMqtt(config)`：
  - 停止旧客户端；
  - `mqttState = 'connecting'`；
  - `telemetry.setSource('mqtt')`；
  - 新 `MqttClient` 连接；
  - 成功日志 `[lingyun-web] mqtt connected`；
  - 首帧日志 `[lingyun-web] first telemetry frame received`。
- **密码只存在 `mqttCfg.url` 字符串里，进程内存态；不写文件、不进前端、不回显、不写日志。**
- 运行时配置的 `allowCommands` 固定为 false，即 `/setup` 打开的账号只用于接收遥测。

> 重要限制：这是“内存配置”，不是持久化配置。部署/重启/实例替换后必须重新填。  
> 部署平台拒绝把真实密码写入 `runtime.environment`（错误 `SERVICE_993511`），但接受非敏感环境变量（如 `REQUIRE_MQTT=1`）。因此才有 `/setup` 方案。

### 5.4 MQTT 客户端（`lib/mqtt-client.js`）

零依赖，手写 MQTT 3.1.1 报文。

| 能力 | 实现 |
| --- | --- |
| 传输 | `net.connect` 或 `tls.connect`（SNI = host） |
| 协议 | MQTT 3.1.1（level 4） |
| Client ID | `lingyun-web-<8位随机hex>`，每次连接随机 |
| Clean Session | 是 |
| Keepalive | 默认 30 秒；每 25 秒发 PINGREQ |
| 订阅 | QoS 0 |
| 发布 | QoS 0 |
| 入站 QoS 1 | 解析 packet id 并回 PUBACK |
| 入站 QoS 2 | 未实现 |
| Retain / Will | 未实现 |
| 断线重连 | 指数退避：1s × 1.7^retry，最大 30s |
| Socket 超时 | 90 秒 |
| TLS 校验 | 默认严格；可用 `MQTT_TLS_INSECURE=true` 关闭 |
| URL 解析 | `mqtt:` / `mqtts:` / `tls:` / `ssl:`；用户名密码自动 decode |

事件：

- `connecting`：开始连接
- `connected`：CONNACK rc=0
- `connect-error`：连接阶段错误
- `connect-refused`：CONNACK 非 0（rc 1–5）
- `error`：已连接后的错误
- `offline` / `disconnected`：断开
- `message(topic, payload)`：收到 PUBLISH
- `subscribed`：收到 SUBACK

CONNACK rc 映射（后端文案）：

| rc | 含义 |
| --- | --- |
| 1 | 协议版本不被支持 |
| 2 | 客户端标识被拒绝 |
| 3 | 服务不可用 |
| 4 | 用户名或密码错误 |
| 5 | 未授权 |

> 该客户端只覆盖本项目需要的最小集合。不要假设它支持 retained、will、QoS2、持久会话。

### 5.5 遥测管线（`lib/telemetry.js`）

#### 5.5.1 常量

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `MAX_CURVE` | 3600 | 曲线点上限（约 30 分钟 @2 Hz） |
| `MAX_LOG` | 500 | 日志上限 |
| `MAX_ALARMS` | 200 | 告警上限 |
| `SESSION_MAX_FRAMES` | 36000 | 单会话帧上限（5 Hz 约 2 小时；0.5 Hz 约 20 小时） |
| 会话数 | 30 | 超过后丢弃最旧会话 |

#### 5.5.2 帧解码 `decodeFrame(payload)`

支持：

- MQTT 纯 JSON：`{"t":...}`
- 协议帧：`0xAA 0x55 <JSON> \n`
- Buffer 或 string
- 解析失败返回 `null`，计入 `badFrames`
- 顶层必须是对象，数组不算有效帧

#### 5.5.3 入口 `ingest(payload, meta)`

顺序：

1. `decodeFrame`；失败 → `badFrames++`，每 20 帧记一次日志。
2. `t` 不是有限数字时，用 `Date.now()/1000` 补齐。
3. **去重**：`t` 与上一帧相同 → `duplicates++`，更新 `lastReceivedAt`，直接返回 `null`。
4. 更新 `lastReceivedAt`（本地接收时间）、`lastDeviceTs`（机载 `t`）、`frameCount`。
5. `normalizeNodes(raw)`：补 `isTemp/isPressure/hasTemp`，兼容旧 `lora` 键。
6. 保存 `frame`，记录会话、采样曲线、评估告警、检查链路恢复。
7. `emit('telemetry', frame)` → server 广播 SSE。

> 关键：**链路超时用 `lastReceivedAt`（本地时间），不用机载 `t`。** 机载 NTP 异常不会影响在线判定。

#### 5.5.4 节点规范化 `normalizeNodes`

- `frame.temp.nodes` → `isTemp:true, isPressure:false, hasTemp: n.p === 0`
- `frame.pressure.nodes` → `isPressure:true, isTemp:false, hasTemp:false`
- 旧 `frame.lora.nodes` 且没有 temp/pressure 时：
  - `p === 1` → pressure
  - 否则 → temp

#### 5.5.5 状态 `status()`

| 字段 | 规则 |
| --- | --- |
| `linkOnline` | `lastReceivedAt > 0` 且 `now - lastReceivedAt < 6000` |
| `safetyFresh` | `now - lastReceivedAt < 3000` |
| `dataRate` | 最近 5 秒帧数 / 时间跨度，0–20 Hz |
| `uptimeSec` | 从服务启动开始 |
| `frameCount` | 解析成功且非重复的帧数 |
| `badFrames` | 解析失败帧数 |
| `duplicates` | `t` 重复帧数 |
| `lastFrameTs` | 最近机载 `t` |
| `devices` | 8 个键：bms/backup/mppt1/mppt2/dcdc/fc/temp/pressure |
| `nodes` | `temp:{online,total}`、`pressure:{online,total}` |
| `alarmsUnconfirmed` | 未确认告警数 |
| `sessionId` | 当前会话 ID |

设备在线判定：

- `temp`：链路在线且至少一个节点 `online===1/true`
- `pressure`：链路在线且至少一个节点 `online===1/true`
- 其他：链路在线且设备段存在且 `online !== false`

> `linkOnline=false` 时所有设备一律离线，避免把最后已知值当实时值。

#### 5.5.6 告警规则（硬编码）

| key | 条件 | 级别 | 内容 |
| --- | --- | --- | --- |
| `bms_soc_low` | `bms.soc < 20` | 严重 | 主电池 SOC 低于 20% |
| `bms_temp_high` | `bms.max_t > 50` | 警告 | 主电池最高温度超过 50℃ |
| `bms_alarm` | `bms.alarm > 0` | 严重 | 主 BMS 上报告警码非 0 |
| `dcdc_fault` | `dcdc.fault !== 0` | 严重 | DCDC 上报故障码非 0 |
| `mppt1_fault` | `mppt1.fault !== 0` | 警告 | 主 MPPT 上报故障码非 0 |
| `mppt2_fault` | `mppt2.fault !== 0` | 警告 | 副 MPPT 上报故障码非 0 |
| `backup_fault` | `backup.fault !== 0` | 严重 | 备用电源上报故障码非 0 |

- 每个 key 有 `alarmState`，只在 false→true 时新增告警，避免每帧重复。
- 告警写入 `alarms`（最多 200），同时写日志并 `emit('alarm')`。
- `confirmAlarm(aid)` / `confirmAllAlarms()`：状态改为“已确认”，并发 `alarm-update`。
- 飞控离线不单独告警，由顶部链路/状态栏呈现。

#### 5.5.7 曲线、会话

- 曲线采样：每 480 ms 一次，记录：
  - `v`：`bms.pack_v`
  - `pv`：`mppt1.pv_p`
  - `outp`：`dcdc.out_p`
  - `i`：`bms.pack_i`
- 会话：
  - 按启动时间生成 `YYYYMMDD_HHmmss`
  - 链路连续（6 秒内有帧）期间为 `recording`
  - 链路断开后，下一帧到达时结束旧会话（`state=ended`、写 `endedAt`）并开启新会话
  - 每帧记录；超过 36000 帧时 `shift()` 并 `dropped++`
  - 最多 30 个会话
  - `sessionList()` 返回倒序摘要
  - `sessionFrames(id, start, count)` 返回分页帧
- 回放 UI 已删除，但 `/api/sessions` 与 `/api/sessions/:id/frames` 仍保留，供未来使用。

#### 5.5.8 模拟源

`startSimulator()` 每 200 ms 生成一帧（5 Hz），字段与真实协议一致：

- `safe_to_control=true`、`power_on_allowed=true`
- `bms`、`backup`、`mppt1`、`mppt2`、`dcdc`、`fc` 全在线
- 102S 主电池 `pack_v≈367V`、`soc≈86%`
- 14S 备用 `pack_v≈48.6V`、`soc=90%`
- 两路 MPPT 功率约 600W / 432W
- DCDC 输出约 250W / 48.1V
- 飞控绕 Liangzhu（30.365, 120.029）小圈飞行
- 11 个温度节点（id 1,2,3,4,5,7,8,9,10,11,12）
- 4 个气压节点（id 1–4）
- 10 个电调（4 推进 + 4 上升 + 2 下降）
- 每 5 帧发一次 `status`（1 秒）

模拟源仅用于演示；`REQUIRE_MQTT=1` 时不会启动；运行时通过 `/setup` 切换到 MQTT 时会立即停止。

### 5.6 指令通道与安全门控

命令白名单：

```js
bms_power:       POWER_OFF / POWER_ON / ACC_CUTOFF
dcdc_power:      POWER_OFF / POWER_ON
mppt_charge:     CHARGE_OFF / CHARGE_ON
dcdc_set_output: 自定义
mppt_write:      自定义
power_all_off:   自定义
```

校验：

- `dcdc_set_output`：电压 40–60 V，限流 0–25 A。
- `mppt_write`：code 1–13，values 必须是 4 个 0–65535 整数。
- 恢复类（`POWER_ON` / `CHARGE_ON`）：
  - 必须 `telemetry.lastReceivedAt` 在 3 秒内；
  - 且 `frame.power_on_allowed === true`；
  - 否则拒绝。
- 下发前提：`allowCommands && cmdTopic && mqtt.connected`。
- 指令 JSON：

```json
{ "type": "cmd", "req_id": 1001, "cmd": "bms_power", "params": { "command": "POWER_OFF" } }
```

- `req_id` 自增，从 1001 开始。
- 待确认 Map 最多 50 条；ACK 超时默认 6 秒（`MQTT_ACK_TIMEOUT`，最小 2 秒）。
- ACK 支持 `req_id` / `reqId`，`accepted` 或 `result !== 'rejected'`。
- 超时或拒绝会写日志、发告警、广播 `power-result`。
- 运行时 `/setup` 配置固定 `allowCommands=false`，因此线上默认只读。

> `safe_to_control` 不用于按钮门控；恢复类只看 `power_on_allowed` 与 3 秒新鲜度。下电类始终允许（但仍需指令通道开启）。

### 5.7 HTTP 服务

- 原生 `http.createServer`，无 Express。
- `URL` 解析请求；异常返回 400。
- `OPTIONS` 返回 204，带 `Access-Control-Allow-Methods/Headers`，但**不返回 `Access-Control-Allow-Origin`**，即不做跨域开放。
- `readJsonBody` 限制 64 KB，JSON 解析失败返回 400。
- `sendJson` 统一 `no-store`、`nosniff`。
- 静态文件：
  - `/` → `/index.html`
  - 路径规范化并校验必须位于 `public/`
  - `.html/.js/.css` → `no-cache, must-revalidate`
  - 其他 → `public, max-age=300`
  - MIME 白名单
  - 支持 HEAD
- 未匹配的 `/api/*` 返回 404 JSON。
- 静态文件不存在返回 404 文本。

### 5.8 SSE

- 路由：`GET /api/stream`
- 最多 30 个客户端；超过返回 503。
- 响应头：`text/event-stream`、`no-cache, no-transform`、`keep-alive`、`X-Accel-Buffering: no`
- 首包 `retry: 3000`
- 连接后立即发送 `state` 快照
- 每 20 秒写 `: keep-alive`
- 事件：
  - `state`：完整初始状态
  - `telemetry`：每帧
  - `status`：每秒
  - `log`：新日志
  - `alarm`：新告警
  - `alarms-sync`：确认后的告警列表
  - `power-result`：指令 ACK/超时/拒绝
- `req.on('close')` 清理客户端和心跳。

## 8. 数据协议映射（速查）

> 完整字段、单位、位定义以 [网页看板对接开发文档_20261113.md](./网页看板对接开发文档_20261113.md) 为准。这里只列 Web 端实际依赖与易错点。

### 8.1 顶层

| 字段 | Web 用途 |
| --- | --- |
| `t` | 去重、`lastFrameTs`；**不用于超时** |
| `safe_to_control` | 当前未用于按钮门控 |
| `power_on_allowed` | 恢复类指令门控 |
| `dcdc_online` / `battery_online` / `backup_online` | 顶层状态；Web 设备在线主要看设备段 |
| `temp.nodes` | 温度节点 |
| `pressure.nodes` | 气压节点 |

### 8.2 条件设备段

| 键 | 缺失含义 | Web 处理 |
| --- | --- | --- |
| `bms` | 离线/未上电 | 设备离线，值显示 `--` |
| `backup` | 离线 | 同上 |
| `mppt1` / `mppt2` | 离线 | 同上 |
| `dcdc` | 离线 | 同上 |
| `fc` | 离线 | 飞控页归零/离线 |

> 协议约定：设备段只要出现，内部 `online` 恒 true。因此判断在线优先看“键是否存在”，同时兼容 `online !== false`。

### 8.3 节点两种形态

在线节点：

```json
{
  "id": 1, "online": 1, "valid": 1, "stale": 0, "p": 0,
  "raw": 12345, "t_ok": 1, "p_ok": 0,
  "temp": 22.9, "pressure": 0, "alarm": 0
}
```

离线节点：

```json
{ "id": 1, "online": 0 }
```

> 必须先判断 `online`，再访问 `temp/pressure`。后端 `normalizeNodes` 会保留原字段并补标记，但不会为离线节点补 `temp/pressure`。

### 8.4 飞控嵌套

| 路径 | 用途 |
| --- | --- |
| `fc.gps.fix/sat/eph/epv` | GPS 状态 |
| `fc.ekf.const_pos/glitch/accel_err` | EKF 健康 |
| `fc.esc.n/rpm/v/i/tmp` | 电调遥测；索引 `< n` 才可信 |
| `fc.mode/armed` | 模式/解锁 |
| `fc.lat/lon/alt/yaw` | 地图/姿态 |

### 8.5 数值规则

- `null` 表示无效（NaN/Inf），前端显示 `--`，不能当 0。
- 浮点最多 4 位有效数字；经纬度/压力 6 位小数。
- `t` 是秒 + 毫秒小数，可能受 NTP 影响；不要用它算超时。
- 离线节点可能只有 `{id, online}`；不要假设字段齐全。

### 8.6 超时与在线

| 判断 | 规则 | 代码 |
| --- | --- | --- |
| 链路在线 | 本地 6 秒内收到帧 | `status.linkOnline` |
| 安全状态新鲜 | 本地 3 秒内收到帧 | `status.safetyFresh` |
| 设备在线 | 链路在线 + 设备段存在 | `status.devices` |
| 节点在线 | 链路在线 + 任一节点 online | `status.nodes` |

### 9.7 常见问题

| 现象 | 可能原因 | 处理 |

| 部署报 `SERVICE_993511` | 把密码写进 `runtime.environment` | 不要写密码；用 `/setup` |

### 9.8 多实例风险（重要）

- 平台站点配置 `max_instances: 10`。
- MQTT 配置是**单进程内存**，不会在实例之间共享。
- 如果 `/setup` 提交到实例 A，而浏览器 SSE 落到实例 B，B 仍显示未配置。
- 观察到的日志显示同一 revision 内 SSE 请求会被取消并重连；低流量下通常只有一个活跃实例，但不能假设。
- 若要生产级稳定，需要：
  1. 平台支持持久化密钥/环境变量（首选）；或
  2. 单实例部署/会话粘滞；或
  3. 外部密钥存储 + 所有实例启动时读取。

## 10. 安全模型与不变量

### 10.1 已实施的安全措施

- MQTT 主机、端口、用户名、密码、主题**不进入前端 bundle、HTML、REST 响应、SSE、日志**。
- `/setup` 密码输入框 `type=password`，提交后清空；不写入 localStorage。
- `POST /api/mqtt/configure` 同源校验 + 2 秒限频 + 64 KB body 限制。
- 静态文件路径穿越保护。
- 错误信息脱敏：未知网络错误只返回“连接失败”。
- 指令通道默认关闭；运行时配置固定 `allowCommands=false`。
- 恢复类指令双重门控：3 秒新鲜度 + `power_on_allowed`。
- 站点私有，依赖平台登录。
- HTML 输出统一 `App.esc()` 转义；日志/状态使用 `textContent` 优先。
- `Cache-Control: no-store` 用于 API；HTML/JS/CSS `no-cache`。

### 10.2 不要破坏的不变量

1. **绝不**把 MQTT 密码/账号写进代码、Git、文档、环境变量或部署描述。
2. **绝不**让浏览器直接连接 MQTT；必须走后端代理。
3. **绝不**用机载 `t` 判断链路超时；用 `lastReceivedAt`。
4. **绝不**在 `linkOnline=false` 时继续显示设备“在线”。
5. **绝不**默认开启指令下行；开启必须显式配置并经过安全评审。
6. **绝不**在离线节点上直接访问 `temp/pressure`。
7. **绝不**把 `null` 当 0。
8. **绝不**在节点 `online` 不是 `1/true` 时读取或展示其实测值；前端统一用 `App.nodeOnline`。
9. 部署后如果要保留 MQTT 配置，先提醒用户重新 `/setup`。

### 10.3 已知安全边界

- 没有应用内登录/角色；能访问私有站点的人都能打开 `/setup`。
- `/setup` 允许把后端指向任意主机（所有者权限内），没有白名单。
- 读接口没有限频；依赖平台 QPS 限制。
- 地图瓦片来自 OpenStreetMap / ArcGIS，会暴露浏览器出口 IP。
- 如果未来开启指令通道，`/api/command` 只有同源 + 平台私有访问，没有二次认证。

## 11. 开发指南

### 11.1 新增一个遥测字段并展示

1. 在协议文档确认字段路径、单位、空值规则。
2. 后端一般不需要改：`ingest` 保留原始帧；除非需要派生/告警。
3. 前端在对应 view 里用 `App.dev('device')[key]` 或 `App.val('device','key')`。
4. 数值显示用 `App.fmt` / `App.fmtInt`；温度用 `App.toTemp`；气压用 `App.pressureText`。
5. 离线/空值必须显示 `--`。

### 11.2 新增告警
