# BT600 遥测网页看板 · 对接开发文档

> **面向对象**：负责开发网页/大屏的前端或全栈工程师
> **目标**：从零接入 BT600 实时遥测数据并在网页中展示
> **版本**：V1 · 2026-11-13
> **状态**：数据链路已实测打通，可开始开发

---

## 1. 数据从哪来

```
BT600 机载 (ROS2)
   ↓ MQTT over TLS
EMQX Cloud（深圳）
   ↓ MQTT over WebSocket
你的网页
```

**你只需要做最后一环**：浏览器通过 WebSocket 订阅 MQTT 主题，收到 JSON 后渲染。

机载侧的采集、打包、上传都已经在跑，不需要你参与。

## 2. 连接参数

| 项        | 值                                                          |
| --------- | ----------------------------------------------------------- |
| 协议      | MQTT over WebSocket Secure                                  |
| 地址      | `wss://kebf30ef.ala.cn-shenzhen.emqxsl.cn:8084/mqtt`      |
| 用户名    | `bt600_onboard`                                           |
| 密码      | **向项目负责人索取**（不要写进代码仓库）              |
| Client ID | 自行生成，建议 `web_<随机串>`，同一账号多个客户端必须不同 |
| Topic     | `bt600/telemetry`                                         |
| QoS       | 0 或 1 均可（服务端以 QoS 0 发布）                          |
| 上报频率  | **0.5 Hz（每 2 秒一帧）**                             |
| 报文大小  | 约 480 字节（全离线时）                                     |
| retain    | 否（新订阅者要等下一帧，最长 2 秒）                         |

**注意**：浏览器**不能**直连 `mqtt://`（TCP 8883），只能用 `wss://` 的 8084 端口。

### 2.1 连接行为（开发者必读）

| 项               | 当前设置   | 对前端的影响                                            |
| ---------------- | ---------- | ------------------------------------------------------- |
| Clean Session    | 是         | **不保留离线消息**：断线期间的数据不会补发        |
| Retain           | 否         | 新订阅者要等下一帧，最长 **2 秒**才看到第一个数据 |
| 遗嘱消息         | 未配置     | 客户端异常断开时，其他客户端**收不到通知**        |
| Keepalive        | 建议 60 秒 | `mqtt.js` 默认值即可                                  |
| 重连间隔         | 建议 3 秒  | 见示例代码 `reconnectPeriod: 3000`                    |
| 单部署连接上限   | 1000       | 远超当前需求                                            |
| 同一账号多客户端 | 允许       | **clientId 必须各不相同**，重复会把前一个踢下线   |

**两个实际影响**：

1. **页面刷新后要等最多 2 秒才有数据** —— 不要在这个窗口里显示“连接失败”。
2. **断线期间的数据永久丢失** —— 需要历史曲线就必须自己落库，MQTT 不提供补发。

**判断链路是否存活**：不要依赖 MQTT 的连接状态（网络抖动时它可能滞后），用**最后一次收到消息的本地时间**：

```js
let lastMsgAt = 0;
client.on('message', () => { lastMsgAt = Date.now(); });

setInterval(() => {
  const stale = Date.now() - lastMsgAt > 6000;   // 超过 3 个周期没数据
  statusEl.textContent = stale ? '数据中断' : '正常';
}, 1000);
```

## 3. 报文结构

每帧是一个 JSON 对象，顶层固定 6 个状态字段，加 2 个必现的节点数组，再按设备在线情况追加 0～6 个设备段。

### 3.1 顶层字段（恒定出现）

| 字段                 | 类型    | 含义                                                              |
| -------------------- | ------- | ----------------------------------------------------------------- |
| `t`                | number  | Unix 时间戳（秒，带毫秒小数）。**不要用它算超时**，见 §6.4 |
| `safe_to_control`  | boolean | 是否允许控制                                                      |
| `power_on_allowed` | boolean | 是否允许上电                                                      |
| `dcdc_online`      | boolean | DCDC 电源在线                                                     |
| `battery_online`   | boolean | 主电池在线                                                        |
| `backup_online`    | boolean | 备用电池在线                                                      |
| `temp`             | object  | 温度节点列表，见 §3.8                                            |
| `pressure`         | object  | 压力节点列表，见 §3.8                                            |

### 3.2 条件段（设备离线时整段消失）

| 键                    | 含义           |
| --------------------- | -------------- |
| `bms`               | 主电池 BMS     |
| `backup`            | 备用电池 BMS   |
| `mppt1` / `mppt2` | 两路光伏控制器 |
| `dcdc`              | DCDC 变换器    |
| `fc`                | 飞控           |

**重要**：这些段只要出现，其内部 `online` 恒为 `true`（离线根本不会输出）。所以判断设备是否在线，**看键在不在**，不用读 `online`。

### 3.3 `bms`（主电池，102 串三元锂）

| 字段                                 | 类型         | 单位 | 说明                                                 |
| ------------------------------------ | ------------ | ---- | ---------------------------------------------------- |
| `online`                           | bool         | —   | 恒 true（段出现即在线）                              |
| `pack_v`                           | number\|null | V    | 电池包总压                                           |
| `pack_i`                           | number\|null | A    | 总电流，**充电为正**、放电为负                 |
| `soc`                              | number\|null | %    | 荷电状态 0–100                                      |
| `rsoc`                             | number\|null | %    | 真实 SOC                                             |
| `soh`                              | number\|null | %    | 健康状态 0–100                                      |
| `max_v` / `min_v`                | number\|null | V    | 最高/最低单体电压                                    |
| `diff_v`                           | number\|null | V    | 单体压差                                             |
| `max_t` / `min_t` / `avg_t`    | number\|null | ℃   | 最高/最低/平均单体温度                               |
| `diff_t`                           | number\|null | ℃   | 单体温差                                             |
| `riso_p` / `riso_n`              | int          | kΩ  | 正/负极绝缘电阻                                      |
| `alarm`                            | int          | —   | **枚举**：`0` 正常 / `1` 故障 / `2` 严重 |
| `fault1` / `fault2` / `fault3` | int          | —   | 一级/二级/三级故障字，**32 位按位解析**        |

**位标志用法**（三级故障字都是 32 位无符号整数）：

```js
const bits = (word, n) => (word & (1 << n)) !== 0;
// fault1 的 bit0 是系统故障，bit16 是一级报警
const sysFault = bits(bms.fault1, 0);
```

> `fault1/2/3` 的具体位定义随 BMS 厂家协议，当前文档未逐位展开。展示策略建议：只要 `alarm !== 0` 或任一 `fault != 0` 就标红，具体位含义在告警详情里做二级展开。

### 3.4 `backup`（备用电池，14S）

| 字段                                           | 类型         | 单位  | 说明                    |
| ---------------------------------------------- | ------------ | ----- | ----------------------- |
| `online`                                     | bool         | —    | 恒 true                 |
| `pack_v` / `pack_i`                        | number\|null | V / A | 总压/总电流（充电为正） |
| `soc` / `soh`                              | number\|null | %     | 0–100                  |
| `max_v` / `min_v` / `diff_v`             | number\|null | V     | 单体电压与压差          |
| `max_t` / `min_t` / `avg_t` / `diff_t` | number\|null | ℃    | 单体温度                |
| `alarm`                                      | int          | —    | 告警字（32 位）         |
| `protect`                                    | int          | —    | 保护字（32 位）         |
| `fault`                                      | int          | —    | 故障字（32 位）         |
| `sys`                                        | int          | —    | 系统状态字（32 位）     |

### 3.8 `temp` / `pressure`（节点数组）

```json
"temp": { "nodes": [ {...}, {...} ] }
```

**`temp.nodes` 通常 11 个** —— LoRa 无线温度探头，id = `1,2,3,4,5,7,8,9,10,11,12`（物理编号，**没有 6 号**）。

**`pressure.nodes` 通常 4 个** —— 有线压力传感器，id 即 Modbus 从机地址，按物理位置：

| id | 位置     |
| -- | -------- |
| 1  | 左副气囊 |
| 2  | 左主气囊 |
| 3  | 右主气囊 |
| 4  | 右副气囊 |

> 压力节点的 id 就是 `1–4`，不是 16–19（早期文档笔误）。

**节点对象有两种形态，这是本文档最重要的一条：**

**在线节点（11 个字段）**

| 字段         | 类型         | 含义                                                   |
| ------------ | ------------ | ------------------------------------------------------ |
| `id`       | int          | 节点编号                                               |
| `online`   | 0/1          | 在线                                                   |
| `valid`    | 0/1          | 数据有效（online 且非 stale）                          |
| `stale`    | 0/1          | 1 = 数值是去抖窗口内沿用的旧值，**界面必须灰显** |
| `p`        | 0/1          | 1 = 压力节点                                           |
| `raw`      | int          | 温度寄存器原始值                                       |
| `t_ok`     | 0/1          | 温度分量读取成功                                       |
| `p_ok`     | 0/1          | 压力分量读取成功                                       |
| `temp`     | number\|null | ℃                                                     |
| `pressure` | number\|null | Pa（有符号）                                           |
| `alarm`    | -1/0/1       | 告警                                                   |

**离线节点（只有 2 个字段）**

```json
{ "id": 1, "online": 0 }
```

2026-11-13 起，离线节点不再输出其余 9 个字段（它们恒为 0，纯属浪费带宽）。整帧因此从 1845 B 降到 480 B。

> **取值前必须先判断 `online`**，否则访问 `node.temp` 会得到 `undefined`，再调用 `.toFixed()` 就会抛异常。

### 3.9 数值精度与类型规则

| 项                   | 规则                                                            | 对前端的影响                                  |
| -------------------- | --------------------------------------------------------------- | --------------------------------------------- |
| 普通浮点（float32）  | **最多 4 位有效数字**（如 `367.2`、`0.0`、`58.42`） | 不要用 `===` 比较浮点；显示时自行决定小数位 |
| 高精度浮点（double） | `lat` / `lon` / 节点压力 固定 **6 位小数**            | 直接展示即可                                  |
| 时间戳 `t`         | 3 位小数秒                                                      |                                               |
| 非有限值             | NaN / Inf 输出 **`null`**                               | 必须判 `null`，不能强转 0                   |
| 整数 / 位标志        | 十进制整数                                                      | 用位运算解析                                  |
| 定长数组             | `fc.esc.rpm/v/i/tmp` 各 **10 项**                       | 索引 `< n` 才可信                           |
| 字符串               | 机载已做 JSON 转义                                              | 标准 `JSON.parse` 自动还原                  |

**精度示例**（同一字段在不同量级下的输出）：

```json
"pack_v": 58.42      // 4 位有效数字
"diff_v": 0.007      // 小数值会自动保留更多小数位
"lat":    31.230400  // 固定 6 位
"t":      1794565325.535
```

### 3.10 两个安全标志的区别

| 字段                 | 判定规则                                                                                                   | 界面用途                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `safe_to_control`  | DCDC 无故障 **且** 主 BMS 电压正常 **且** 备用 BMS 在线无故障，**三者全 ok** 才 `true` | 按 2026-10-18 定稿，**不用于按钮置灰、不显示为“总体状态”** |
| `power_on_allowed` | 只要不存在“**在线却故障**”的关键设备即为 `true`；**全部设备离线（冷启动）时也是 `true`** | **恢复类按钮**（上电 / 开充）的置灰依据                      |

**关键差异**

```
设备全部离线（冷启动）：
  safe_to_control   = false   ← 严格，任一设备离线就不放行
  power_on_allowed  = true    ← 宽松，离线不算故障
```

**为什么这样设计**：102S 主电池和 MPPT 都带手动硬件开关，设备离线多数是“未上电的正常待机”。旧规则把上电绑定到 `safe_to_control`，导致“全部下电后所有设备离线 → 再也无法上电”的死锁。

**其他规则**

- **下电类操作**（断电 / 关充）**始终允许**，不受任何标志限制
- 安全状态超过 **3 秒**未更新时，两个标志**都置 `false`**（不沿用陈旧的 true）
- 两个字段目前都在报文中，属于向后兼容保留

## 6. 五条必须遵守的规则

### 6.1 设备段可能整段不存在

```js
// ❌ 会崩
const v = data.bms.pack_v.toFixed(2);

// ✅ 正确
const v = data.bms ? data.bms.pack_v?.toFixed(2) : null;
```

同理，`mppt1` / `mppt2` / `dcdc` / `fc` / `backup` 都可能不存在。

### 6.2 离线节点只有两个字段

```js
// ❌ 会崩（offline 节点没有 temp）
nodes.forEach(n => render(n.temp.toFixed(1)));

// ✅ 正确
nodes.forEach(n => render(n.online === 1 ? n.temp?.toFixed(1) : '—'));
```

### 6.3 `null` 不等于 0

机载把 `NaN` / `Inf` 输出为 `null`，表示“这个值无效”。**不要强转成 0**，否则界面上会出现假的 0 V、0 A。

### 6.4 `t` 不是单调时钟

NTP 对时会让 `t` 跳变甚至倒退。判断“数据是否新鲜”要用**本地接收时间**：

```js
let lastRecvAt = Date.now();
client.on('message', () => { lastRecvAt = Date.now(); });
// 超过 6 秒没收到 → 判定链路断开
```

### 6.5 重复帧要幂等

QoS 1 在极端情况下可能重复投递。如果做计数、累计、告警触发，要用 `t` 做去重。

## 9. 常见问题

**Q：为什么连上了但一直没数据？**
A：检查 topic 是否为 `bt600/telemetry`（不是 `bt600/test`）。前者是生产数据，后者是测试实例。

**Q：订阅到了但字段比文档少？**
A：设备离线。等 BMS/MPPT 上电后，对应段会自动出现，代码不用改。

**Q：能不能直接连 8883 端口？**
A：浏览器不行，只能用 8084 的 WebSocket。8883 是给后端程序用的。

**Q：密码能写在前端吗？**
A：**生产环境不要**。当前阶段（内部验证）可以临时写死，上线前必须改成后端中转 + 自己的鉴权。

**Q：数据延迟多少？**
A：机载采集 0.5 Hz → MQTT 推送，端到端通常 1～2 秒。

**Q：历史曲线怎么做？**
A：EMQX 不存历史。需要后端订阅后写入时序库（InfluxDB / TDengine），前端查库。目前尚未实现。
